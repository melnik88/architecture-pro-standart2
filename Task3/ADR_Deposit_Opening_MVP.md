### **Решение**

#### Архитектурные решения

**1. Микросервисная архитектура для новых компонентов**
Для реализации MVP предлагается создать новые микросервисы, которые будут интегрироваться с существующими системами:

- **Сервис управления депозитами** - центральный компонент для обработки заявок на депозиты и передачи их в АБС и кол-центр
- **Сервис управления ставками** - централизованная система для управления ставками по депозитам

**2. Кэширование данных**
Внедрение Redis для кэширования:
- Актуальных ставок по депозитам
- Персонализированных предложений
- Справочных данных для ускорения отклика

**3. Прямая интеграция**
- Сайт и интернет-банк работают напрямую с микросервисами через REST API
- Deposit Service интегрируется напрямую с АБС и системой кол-центра
- Упрощенная архитектура без лишних промежуточных слоев

#### Диаграммы

**Диаграмма контекста C4** представлена в файле [`context_diagram.puml`](context_diagram.puml)

**Диаграмма контейнеров C4** представлена в файле [`container_diagram.puml`](container_diagram.puml)

**Описание диаграмм:**

**Контекстная диаграмма C4** показывает банковскую систему "Стандарт" как единое целое и её взаимодействие с внешними пользователями и системами для MVP депозитов:
- **Пользователи**: клиенты (подают заявки через сайт или интернет-банк, приходят в отделения), менеджеры кол-центра, менеджеры фронт-офиса (проводят идентификацию в отделениях), менеджеры бэк-офиса депозитов и менеджеры бэк-офиса кредитов (участвуют в расчете персонализированных ставок)
- **Внешние системы**: СМС-шлюз телеком-оператора для уведомлений
- **Основные потоки**: подача заявок на депозиты через разные каналы, обработка заявок, расчет персонализированных ставок, личная идентификация в отделениях, СМС-уведомления о статусе

**Диаграмма контейнеров C4** детализирует внутреннюю архитектуру MVP решения для депозитов:

**Интернет-банк (детализация):**
- **Web UI** (ASP.NET MVC 4.5) - пользовательский интерфейс для подачи заявок на депозиты
- **Core Logic** (ASP.NET MVC 4.5) - бизнес-логика интернет-банка
- **Database** (MS SQL Server) - данные интернет-банка

**АБС - Автоматизированная Банковская Система (детализация):**
- **Desktop Client** (Delphi) - рабочие места сотрудников для обработки депозитных заявок
- **Business Logic** (PL/SQL Procedures) - основная бизнес-логика банка
- **Oracle Database** - основная база данных банка с клиентскими данными и депозитами
- **ABS Integration Adapter** (Java Spring Boot) - адаптер для безопасной интеграции с новыми сервисами

**Новые микросервисы для MVP депозитов:**
- **Deposit Service** (Java Spring Boot) - промежуточный слой для приема заявок с цифровых каналов и передачи в АБС и кол-центр
- **Rate Management Service** (Java Spring Boot) - сервис для передачи ставок по депозитам в АБС и цифровые каналы

**Инфраструктурные компоненты:**
- **Redis Cache** - кэширование ставок по депозитам и справочных данных для повышения производительности

**Существующие системы, задействованные в MVP:**
- **Веб-сайт банка** (React.js + PHP) - маркетинговая информация и подача заявок на депозиты
- **Система кол-центра** (React.js + Java Spring Boot + PostgreSQL) - CRM функционал для обработки заявок с сайта

#### Технологический стек

**Новые компоненты:**
- **Сервис управления депозитами**: Java Spring Boot + PostgreSQL
- **Сервис управления ставками**: Java Spring Boot + PostgreSQL
- **Кэш**: Redis
- **Мониторинг**: Prometheus + Grafana

**Интеграция с существующими системами:**
- АБС (Oracle + PL/SQL) - через прямую интеграцию для депозитных операций
- Интернет-банк (ASP.NET MVC 4.5) - через REST API для получения ставок и подачи заявок
- Система кол-центра (Java Spring Boot) - через REST API для обработки заявок с сайта
- СМС-шлюз - через существующий API для уведомлений по депозитам

#### Логика принятия решений

1. **Выбор Java Spring Boot** - команда АБС имеет экспертизу в Java, совместимость с системой кол-центра
2. **PostgreSQL для новых сервисов** - уже используется в системе кол-центра, команда знакома с технологией
3. **Микросервисная архитектура** - упрощение разработки и поддержки, возможность независимого масштабирования
4. **Redis** - решение проблемы производительности справочных данных

### **Альтернативы**

**Альтернатива 1: Доработка существующего интернет-банка**
- Добавление функционала депозитов непосредственно в ASP.NET MVC приложение
- Прямая интеграция с АБС через базу данных
- **Недостатки**: Перегрузка АБС, зависимость от подрядчика, сложность масштабирования

**Альтернатива 2: Полная замена интернет-банка**
- Создание нового интернет-банка на современном стеке
- Миграция всех существующих функций
- **Недостатки**: Высокие затраты, длительные сроки, высокие риски

**Альтернатива 3: Использование готового банковского решения**
- Внедрение коробочного продукта для управления депозитами
- **Недостатки**: Высокая стоимость лицензий, сложность интеграции, зависимость от вендора

### **Недостатки, ограничения, риски**

**Недостатки:**
1. **Сложность архитектуры** - увеличение количества компонентов усложняет поддержку
2. **Необходимость обучения команды** - новые технологии требуют времени на освоение
3. **Дополнительная инфраструктура** - требуются ресурсы для Kafka, Redis, новых сервисов

**Ограничения:**
1. **Производительность АБС** - вертикальное масштабирование только, ограниченная пропускная способность
2. **Синхронизация данных** - текущая интеграция АБС и других систем происходит раз в сутки
3. **Зависимость от подрядчика** - ограниченные возможности доработки ядра интернет-банка
4. **Законодательные требования** - обязательная личная идентификация новых клиентов

**Риски:**
1. **Производительность** - новая нагрузка может повлиять на работу АБС несмотря на меры предосторожности
2. **Интеграция** - сложность интеграции между множеством систем может привести к задержкам
3. **Безопасность** - увеличение количества интеграций повышает поверхность атак
4. **Операционные риски** - необходимость поддержки дополнительных компонентов
5. **Масштабирование** - неопределенность в росте нагрузки от новых клиентов

**Меры по снижению рисков:**
1. Поэтапное внедрение с тщательным мониторингом производительности АБС
2. Комплексное тестирование интеграций на тестовой среде
3. Внедрение централизованного мониторинга и алертинга
4. Подготовка детальной документации и обучение команд
5. Планирование capacity planning на основе прогнозов роста клиентской базы
