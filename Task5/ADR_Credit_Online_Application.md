### **Решение**

#### Архитектурные решения

**1. Микросервисная архитектура для кредитного процесса**

Для реализации онлайн-подачи кредитных заявок предлагается создать новый микросервис, который будет интегрироваться с существующими системами:

- **Credit Application Service** - центральный компонент для приема заявок с сайта и интернет-банка, валидации данных, взаимодействия с системой скоринга и передачи одобренных заявок в кредитный конвейер

**2. Асинхронная обработка через Kafka**

Внедрение Apache Kafka для:
- Асинхронной передачи ВСЕХ заявок из Credit Application Service в систему кредитного скоринга
- Гарантированной доставки сообщений
- Буферизации заявок при пиковых нагрузках
- Разгрузки АБС от синхронных запросов
- Горизонтального масштабирования обработки заявок

**3. Горизонтальное масштабирование системы кредитного скоринга**

- **Предварительный расчет скоринга** для существующих клиентов в ночное время (когда АБС не перегружена)
- **Кэширование предодобренных предложений** в Redis с TTL 24 часа
- **Увеличение количества инстансов скоринга** для обработки онлайн-заявок из Kafka
- **Асинхронная обработка** всех онлайн-заявок через Kafka Consumer
- **Фильтрация** - только одобренные заявки передаются в Кредитный конвейер

**4. Интеграция с существующими системами**

- **Интернет-банк** → Credit Application Service (REST API)
- **Сайт** → Credit Application Service (REST API)
- **Credit Application Service** → Kafka (Producer - ВСЕ заявки)
- **Система кредитного скоринга** ← Kafka (Consumer - обработка заявок)
- **Система кредитного скоринга** → Кредитный конвейер (передача одобренных заявок)
- **Система кредитного скоринга** → БКИ (REST API - запрос кредитных историй)
- **АБС** → Система кредитного скоринга (ночная синхронизация данных клиентов, read-only)
- **Кредитный конвейер** → АБС (запись данных по одобренным кредитам)
- **АБС** → СМС-шлюз (REST API - отправка уведомлений клиентам)

**5. Модернизация интернет-банка**

Для поддержки новой функциональности потребуется:
- Добавление UI для отображения предодобренных предложений
- Интеграция с Credit Application Service через REST API
- Использование существующего функционала СМС-подтверждения

#### Технологический стек

**Новые компоненты:**
- **Credit Application Service**: Java Spring Boot + PostgreSQL
- **Очередь сообщений**: Apache Kafka
- **Кэш**: Redis (расширение существующего для депозитов)
- **Мониторинг**: Prometheus + Grafana (расширение существующего)

**Модернизация существующих систем:**
- **Система кредитного скоринга**: расширение Python Flask API, добавление планировщика для ночных расчетов
- **Интернет-банк**: доработка ASP.NET MVC для отображения предложений и подачи заявок

**Интеграции:**
- Интернет-банк → Credit Application Service (REST API)
- Сайт → Credit Application Service (REST API)
- Credit Application Service → Kafka (Producer - ВСЕ заявки)
- Система кредитного скоринга ← Kafka (Consumer - обработка заявок)
- Система кредитного скоринга → Кредитный конвейер (одобренные заявки)
- Система кредитного скоринга → БКИ (REST API - запрос кредитных историй)
- АБС → Система кредитного скоринга (ночная синхронизация, read-only)
- Кредитный конвейер → АБС (запись одобренных кредитов)
- АБС → СМС-шлюз (REST API - уведомления клиентам)

#### Логика принятия решений

1. **Выбор Java Spring Boot для Credit Application Service** - совместимость с кредитным конвейером и системой кол-центра, наличие экспертизы в команде АБС

2. **Использование Apache Kafka между Credit Application Service и системой скоринга** - требование из FURPS+ для асинхронной коммуникации, гарантированная доставка сообщений, буферизация при пиковых нагрузках

3. **Горизонтальное масштабирование системы скоринга** - система уже поддерживает масштабирование (из task2.md), добавление инстансов для обработки онлайн-заявок

4. **Предварительный расчет скоринга в ночное время** - минимизация нагрузки на АБС в рабочее время, мгновенное отображение предложений клиентам

5. **Кэширование предодобренных предложений в Redis** - быстрый отклик при отображении предложений в интернет-банке

6. **Единая точка обработки заявок** - все заявки проходят через систему скоринга, что упрощает архитектуру и исключает дублирование логики

7. **Фильтрация на уровне скоринга** - только одобренные заявки попадают в Кредитный конвейер, снижая нагрузку на менеджеров

8. **Упрощение Credit Application Service** - сервис выполняет только роль API Gateway без бизнес-логики принятия решений

### **Альтернативы**

**Альтернатива 1: Синхронная интеграция с кредитным конвейером**
- **Преимущества**: Простота реализации, мгновенная передача заявок
- **Недостатки**: Риск перегрузки кредитного конвейера, отсутствие буферизации при пиковых нагрузках, сложность обработки сбоев

**Альтернатива 2: Расчет скоринга в реальном времени для всех клиентов**
- **Преимущества**: Всегда актуальные данные, отсутствие кэширования
- **Недостатки**: Высокая нагрузка на АБС и БКИ в рабочее время, медленный отклик для клиентов, высокие затраты на запросы к БКИ

**Альтернатива 3: Прямая интеграция интернет-банка с кредитным конвейером**
- **Преимущества**: Меньше компонентов в архитектуре
- **Недостатки**: Нарушение принципа единой точки входа, дублирование логики валидации, сложность мониторинга

### **Недостатки, ограничения, риски**

**Недостатки:**
1. **Увеличение сложности архитектуры** - добавление новых компонентов (Kafka, Credit Application Service) усложняет общую систему
2. **Зависимость от внешней системы БКИ** - доступность и производительность скоринга зависит от внешнего API
3. **Задержка актуализации предодобренных предложений** - предложения обновляются раз в сутки, изменения в данных клиента отражаются с задержкой
4. **Необходимость обучения команды** - Kafka требует специфических знаний для настройки и поддержки

**Ограничения:**
1. **Производительность АБС** - ограничение на частоту синхронизации данных для скоринга (только в ночное время)
2. **Законодательные требования** - обязательная личная идентификация новых клиентов в отделении перед выдачей кредита
3. **Текущая архитектура интернет-банка** - ASP.NET MVC 4.5 не поддерживает нативную работу с Kafka, требуется промежуточный слой
4. **Ограничения БКИ** - лимиты на количество запросов, стоимость запросов, возможные задержки в ответах
5. **Синхронизация данных с кредитным конвейером** - текущая интеграция АБС и конвейера происходит раз в сутки, требуется модернизация

**Риски и меры по их снижению:**

1. **Риск перегрузки АБС при синхронизации данных**
   - Мера: Синхронизация только в ночное время с ограничением скорости запросов
   - Мера: Мониторинг нагрузки на АБС и автоматическое замедление при превышении порогов

2. **Риск недоступности БКИ**
   - Мера: Реализация retry-механизмов с экспоненциальной задержкой
   - Мера: Кэширование результатов запросов к БКИ
   - Мера: Fallback на ручную обработку заявок при длительной недоступности

3. **Риск потери сообщений в Kafka**
   - Мера: Настройка репликации Kafka (минимум 3 брокера)
   - Мера: Подтверждение доставки сообщений (acknowledgments)
   - Мера: Мониторинг очередей и алертинг при задержках

4. **Риск мошенничества при онлайн-подаче заявок**
   - Мера: Многофакторная аутентификация (СМС-коды)
   - Мера: Проверка данных в БКИ
   - Мера: Ограничение суммы кредита для онлайн-заявок
   - Мера: Обязательная личная идентификация в отделении перед выдачей

5. **Риск несоответствия предодобренных предложений актуальным данным**
   - Мера: TTL кэша 24 часа с автоматической инвалидацией
   - Мера: Повторная проверка скоринга при подаче заявки
   - Мера: Информирование клиента о предварительном характере предложения

6. **Риск сложности интеграции множества систем**
   - Мера: Поэтапное внедрение с тщательным тестированием
   - Мера: Создание интеграционных тестов для всех взаимодействий
   - Мера: Детальная документация всех API и интеграций

7. **Риск увеличения операционных затрат**
   - Мера: Автоматизация мониторинга и алертинга
   - Мера: Использование существующей инфраструктуры (Redis, мониторинг)
   - Мера: Обучение команды для самостоятельной поддержки

8. **Риск превышения бюджета на запросы к БКИ**
   - Мера: Кэширование результатов запросов
   - Мера: Ограничение частоты запросов для одного клиента
   - Мера: Мониторинг количества и стоимости запросов
